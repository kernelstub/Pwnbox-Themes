# Install a theme

Themes are part of the Pwnbox flake. Installing one means adding its palette
and wallpaper to your Pwnbox checkout, staging the files with git, rebuilding
the system, and selecting the theme in the picker.

## Before you start

- A working Pwnbox installation.
- The Pwnbox flake checkout you used for that installation (the directory
  containing `flake.nix` and `dotfiles/`). The examples use `~/pwnbox`.
- A user with `sudo` access, for the rebuild.
- The `Pwnbox-Themes` repository cloned somewhere:

  ```bash
  git clone https://github.com/kernelstub/Pwnbox-Themes.git
  cd Pwnbox-Themes
  ```

Themes cannot be installed by dropping files into `~/.config/pwnbox/themes`:
that directory is generated by home-manager, its entries point into the Nix
store, and changes do not survive a rebuild. Add themes to the flake instead.

## One-command install

```bash
./scripts/install-theme.sh midnight
```

The script:

1. Finds your Pwnbox checkout (`$PWNBOX_DIR`, the current directory,
   `~/pwnbox`, or `~/Pwnbox`).
2. Validates the theme with `scripts/validate-theme.py`.
3. Copies only `theme.conf` and its wallpaper to
   `dotfiles/themes/midnight/`.
4. Stages the folder with `git add` when the checkout is a git repository.
5. Runs `./scripts/install.sh switch` to rebuild and activate.

If your checkout is somewhere else, or the script finds the wrong one:

```bash
./scripts/install-theme.sh midnight --flake ~/src/Pwnbox
```

Available options:

| Option | Meaning |
| --- | --- |
| `-f`, `--flake DIR` | Pwnbox checkout to install into |
| `-N`, `--no-rebuild` | Copy and stage only; rebuild later with `upd` |
| `--force` | Replace an already installed folder with the same name |
| `--skip-validation` | Do not run the validator first (local experiments only) |
| `--dry-run` | Print what would happen without changing anything |
| `-l`, `--list` | List installable themes and exit |
| `-h`, `--help` | Show usage |

Examples:

```bash
./scripts/install-theme.sh --list
./scripts/install-theme.sh ember --flake ~/pwnbox
./scripts/install-theme.sh ember --no-rebuild
./scripts/install-theme.sh ember --force
./scripts/install-theme.sh ember --dry-run
```

If auto-detection fails, pass `--flake`. If you run the script from inside
your Pwnbox checkout (using its full path), auto-detection uses the current
directory.

## Select the theme

After a successful rebuild:

```text
ALT + S -> THEME -> Custom -> <theme name>
```

Or run the picker directly:

```bash
pwnbox-theme custom
```

The picker shows each theme as a card with its wallpaper and display name.
The active theme is remembered in `~/.cache/pwnbox/theme/custom-theme` and is
re-applied on login.

## Manual install

If you prefer not to use the installer:

```bash
# 1. create the theme directory in your Pwnbox checkout
mkdir -p ~/pwnbox/dotfiles/themes/midnight

# 2. copy the two files Pwnbox needs
cp themes/midnight/theme.conf \
   themes/midnight/wallpaper.png \
   ~/pwnbox/dotfiles/themes/midnight/

# 3. stage them, otherwise the flake will not see the folder
cd ~/pwnbox
git add dotfiles/themes/midnight

# 4. rebuild and activate
upd
# or: ./scripts/install.sh switch
```

Then pick the theme from `ALT + S -> THEME -> Custom`.

The `preview.png` and `README.md` in the repository are for the gallery and
documentation. Pwnbox does not need them; the installer intentionally leaves
them out. If you copy the whole folder, Pwnbox still uses only the wallpaper
named in `wallpaper =`; the extra files are harmless.

## Update a theme

Re-run the installer with `--force`:

```bash
./scripts/install-theme.sh midnight --force
```

This replaces the installed folder, stages it, and rebuilds. If the theme is
currently active, Pwnbox re-applies its wallpaper during activation. Preview
thumbnails are keyed on the wallpaper path and modification time, so they
refresh automatically. If an app still shows the old colours, restart that app
(see [Troubleshooting](../reference/troubleshooting.md)).

## Uninstall a theme

Select a different theme first, then remove the folder from the flake:

```bash
cd ~/pwnbox
git rm -r dotfiles/themes/midnight
upd
```

If `git rm` reports "did not match any files", the folder was never staged.
Remove it with `rm -rf dotfiles/themes/midnight` and stage the change with
`git add -A dotfiles/themes`.

To reset to the built-in Monochrome palette after removal:

```bash
pwnbox-theme monochrome
```

## Where a theme lives

| Location | Purpose |
| --- | --- |
| `Pwnbox-Themes/themes/<name>/` | Source package in this repository |
| `~/pwnbox/dotfiles/themes/<name>/` | Theme inside your Pwnbox flake |
| `~/.config/pwnbox/themes/<name>/` | Read-only link created by home-manager |
| `~/.cache/pwnbox/theme/custom-theme` | Name of the active custom theme |
| `~/.cache/pwnbox/theme/thumbs/` | Cached picker thumbnails |

Do not edit the `~/.config/pwnbox/themes` link. Change the flake folder and
rebuild.

For how Pwnbox consumes the palette and which apps update live, see Pwnbox's
[theme documentation](https://github.com/kernelstub/Pwnbox/blob/main/docs/usage/themes.md).

## Multiple machines

Because the theme is committed to the flake, every machine that rebuilds from
the same checkout gets it. Copying the folder into the checkout and running
`git add` is enough; commit and push if you want it on other machines or in
your own fork.
