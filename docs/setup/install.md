# Install a theme

Themes are part of the Pwnbox flake. Installing one means copying its folder
into `dotfiles/themes/`, staging the files with git, rebuilding the system,
and selecting the theme in the picker.

This repository currently ships only the template, so there is nothing to
install until a community theme is merged.

## Before you start

- A working Pwnbox installation.
- The Pwnbox flake checkout you used for that installation (the directory
  containing `flake.nix` and `dotfiles/`). The examples use `~/pwnbox`.
- A user with `sudo` access, for the rebuild.
- The `Pwnbox-Themes` repository cloned somewhere:

  ```bash
  git clone https://github.com/kernelstub/Pwnbox-Themes.git
  cd Pwnbox-Themes
  ```

## Copy the theme

The examples use `aurora` as a placeholder theme name. Replace it with the
folder you want to install.

```bash
cp -r themes/aurora ~/pwnbox/dotfiles/themes/

cd ~/pwnbox
git add dotfiles/themes/aurora
upd
```

The `git add` is required. The Pwnbox flake only sees files tracked by git, so
an untracked theme is silently invisible even after a rebuild.

Pwnbox only needs `theme.conf` and the wallpaper named in it. Copying the
whole folder is fine; `preview.png` and `README.md` are harmless extras.

If your checkout is not a git repository, copy the folder and rebuild from
the checkout with `nixos-rebuild switch --flake .#<host>`; there is nothing to
stage.

## Select the theme

After a successful rebuild:

```text
ALT + S -> THEME -> Custom -> <theme name>
```

Or run the picker directly:

```bash
pwnbox-theme custom
```

The picker shows each theme as a card with its wallpaper and display name.
The active theme is remembered in `~/.cache/pwnbox/theme/custom-theme` and is
re-applied on login.

## Update a theme

Replace the installed folder, stage the change and rebuild:

```bash
rm -rf ~/pwnbox/dotfiles/themes/aurora
cp -r themes/aurora ~/pwnbox/dotfiles/themes/

cd ~/pwnbox
git add -A dotfiles/themes/aurora
upd
```

If the theme is currently active, Pwnbox re-applies its wallpaper during
activation. Preview thumbnails are keyed on the wallpaper path and
modification time, so they refresh automatically. If an app still shows the
old colours, restart that app (see
[Troubleshooting](../reference/troubleshooting.md)).

## Uninstall a theme

Select a different theme first, then remove the folder from the flake:

```bash
cd ~/pwnbox
git rm -r dotfiles/themes/aurora
upd
```

If `git rm` reports "did not match any files", the folder was never staged.
Remove it with `rm -rf dotfiles/themes/aurora` and stage the change with
`git add -A dotfiles/themes`.

To reset to the built-in Monochrome palette after removal:

```bash
pwnbox-theme monochrome
```

## Where a theme lives

| Location | Purpose |
| --- | --- |
| `Pwnbox-Themes/themes/<name>/` | Source package in this repository |
| `~/pwnbox/dotfiles/themes/<name>/` | Theme inside your Pwnbox flake |
| `~/.config/pwnbox/themes/<name>/` | Read-only link created by home-manager |
| `~/.cache/pwnbox/theme/custom-theme` | Name of the active custom theme |
| `~/.cache/pwnbox/theme/thumbs/` | Cached picker thumbnails |

Themes cannot be installed by dropping files into `~/.config/pwnbox/themes`:
that directory is generated by home-manager, its entries point into the Nix
store, and changes do not survive a rebuild. Add themes to the flake instead.

For how Pwnbox consumes the palette and which apps update live, see Pwnbox's
[theme documentation](https://github.com/kernelstub/Pwnbox/blob/main/docs/usage/themes.md).

## Multiple machines

Because the theme is committed to the flake, every machine that rebuilds from
the same checkout gets it. Copying the folder into the checkout and running
`git add` is enough; commit and push if you want it on other machines or in
your own fork.
